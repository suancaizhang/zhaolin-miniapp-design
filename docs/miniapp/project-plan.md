# 小程序项目规划

当前执行范围按 2026-10-24 的调整：**1.0.0 静态小程序先上线，运行不依赖 `admin/` 或 `server/`**。既有完整后台方案保留供后续维护。本文件说明当前实现、交付边界与剩余验收，不将历史命令行通过记录或 HTML 演示当作微信上线证据。恢复与运行入口见 [README](../../README.md)，平台操作见[发布清单](release-checklist.md)，实际证据见[测试报告](test-report.md)。

## 产品与当前内容

- 产品名称：召麐个人作品馆；面向普通观众，兼顾绘画爱好者。
- 长期目标：集中欣赏作品整体、局部与创作过程，阅读可靠说明并转发作品入口。当前静态阶段展示图像及画面观察，不承诺已经核实同一作品的创作时间线。
- 当前内容：30 幅图像、6 幅精选、4 个策展分组（壁画人物、手势与持物、一笔一线、创作现场）。标题和描述是描述性整理，不能当作正式作品名或作者自述。
- 事实入口：[miniapp/lib/local-catalog.ts](../../miniapp/lib/local-catalog.ts)；图片来源和派生文件见 [materials/xiaohongshu/sources.json](../../materials/xiaohongshu/sources.json)。[server/source-index.json](../../server/source-index.json) 是43条历史来源笔记的初始待确认索引，不是43件已确认作品，也不代表30张封面已经完成作品归并。
- 编号边界：采集清单的 `coverage` 明确未取得笔记ID和完整详情图组；静态 `source-XX` 与网格位置不是43条笔记的已确认映射，不能按相同编号合并。
- 年份、材料、尺寸与记录日期没有可靠值时留空；当前不显示未经确认的创作状态，不以发布日期替代创作日期。
- 观众免登录只读。内容由本地源码和素材清单维护，更新需要构建并发布新包；后台保存不会同步到当前小程序。
- 长期术语及需求见[产品决策](../../PRODUCT-DECISIONS.md)、[词汇表](../../GLOSSARY.md)、[实现方案](../../IMPLEMENTATION-PROPOSAL.md)。2026-10-22 的需求和完整设计确认保留为历史基线，当前首发优先级见[决策记录](decisions.md)。

## 首发范围与成功标准

当前闭环：维护本地图像目录及素材 → 构建小程序包 → 微信工具编译与预览 → 平台上传、审核和发布 → 观众浏览/放大 → 朋友接收端按稳定 ID 打开对应图像。

- 必须覆盖：6幅精选、30幅图像、4组浏览、真实整体/局部标签、画面观察、原生图片预览、可回退的导航、朋友分享入口。
- 静态内容语义：每个条目当前只有一图；`coverImageId` 与 `overallImageId` 均指主展示图，图可以是局部。详情根据 `image.view` 显示真实标签，不把后台「整体图必须整体」校验套到静态数据。
- 暂不纳入：观众登录、收藏、下载按钮、联系作者、评论、交易、教学、自动抓取同步、后台部署和云开发。系统预览菜单关闭不等于阻止截图或一切系统保存行为。
- 成功标准：微信工具实际编译与包体满足平台要求，安卓/iPhone 可浏览包内图和打开系统预览，分享接收端冷启动可读到正确 ID，无效 ID 可返回图集；公众平台审核和正式发布取得实际证据。
- 原43条来源核对、正式作品归并、两位维护者共享后台仍是后续产品工作，不能因本次静态首发或30张封面采集就标记完成。

## 页面、视觉与数据契约

B「TDesign品牌定制」方向及完整设计于2026-10-22获确认。当前暖白卡片、朱红强调、系统字体、图片保比例与原生 tab 延续该方向；实际数值和组件映射见[设计系统](design-system.md)。375×812、状态栏、胶囊与安全区是 HTML 设计标尺，生产使用原生导航和设备安全区；不是固定手机画布。

原生 tab 使用 `miniapp/assets/` 内的普通/选中 PNG。图集默认双列，视口不超过350px改为单列；详情主图和观察图通过 `gallery-image` 使用 `aspectFit`。卡片和详情都不显示创作状态。

[shared/types.ts](../../shared/types.ts) 仍定义后台作品、创作记录、系列和来源模型。静态条目是其局部复用：不含 `status`，元信息为空，`sourceRefs=[]`；观察记录按可选 `stage` 生成，当前没有真实日期。`presentation.ts` 按线稿/设色/完成效果组织非空组，页面标题为「画面观察」。阶段与视角始终分开，不将分组解释为实际创作先后。

静态列表按 `localCatalog` 数组顺序展示；当前查询层不按 `sort` 重新排序。修改精选或顺序应同步调整条目和数组，不沿用后台「只改排序字段即可重排」的假设。多个分组引用同一稳定图像 ID。

## 内容维护与构建

1. 在 `miniapp/lib/local-catalog.ts` 维护稳定 ID、描述性名称、画面说明、视角、精选和分组；新增/更换图像同时维护素材清单及对应采集文件。
2. [build-gallery-images.mjs](../../scripts/build-gallery-images.mjs)依据 `materials/xiaohongshu/sources.json` 校验输入 SHA256，生成展示图、缩略图与5:4补边分享 JPEG，并回写派生文件元数据。它不负责作者确认、作品归并或从后台导出。
3. [build-miniapp.mjs](../../scripts/build-miniapp.mjs)从固定的 TDesign 1.17.0 依赖生成所需组件、内嵌图标字体并保留许可证。生成产物不能作为手工维护入口。
4. 根 `npm run build` 调用小程序类型检查、图片生成、组件生成及包静态校验。微信开发者工具再负责实际编译、预览与上传；构建不会发布小程序。

依赖恢复和项目内 Node/npm 调用方式以 [README](../../README.md)为准。构建会写素材清单和生成目录；文档核对与隔离验证不应读取或写入真实 `data/`。不要为静态首发启动业务服务、建真实维护者账号或导入原型数据。

## 生命周期、预览与分享

- 首页、图集和系列在 `onShow` 重新读取包内目录，四页支持下拉刷新；这不是后台内容同步。列表已载入后的刷新失败保留旧内容与错误反馈。
- 详情在 `onLoad` 接收 `id`，重新加载前清空旧详情和预览列表；缺少或无效 ID 显示未找到和恢复入口。图片错误由组件局部提示并重试。
- 预览先通过 `wx.getImageInfo` 取得平台路径，再 `wx.previewImage`；设定 `showmenu:false`，失败可重试。微信实际读图和预览效果仍需平台验证。
- 系列和详情返回：页面栈有上页则 `navigateBack`；无上页或返回失败则切换图集。列表滚动恢复依赖平台表现，不将历史 HTML 的手工滚动记录当作生产保证。
- 朋友分享：详情加载成功后开放 `shareAppMessage`，返回 `/pages/work/index?id=稳定ID`、标题和本地分享封面；没有 `onShareTimeline`。
- 接收者独立读其当前小程序包中的目录，不依赖发送端内存或本地服务器。跨版本 ID 可用性、系统封面、真实朋友冷启动仍需验证；关闭后重开也不会读到后台最新编辑。

## 历史后台验收与当前静态验收

2026-10-22 完整方案包含两位同权维护者、作品与创作记录、系列/精选排序、来源映射、Node/SQLite与独立图片目录。后台的身份、会话、CSRF、图片处理和字段校验是保留工程的验收范围；它们不替代静态包内30图与微信分享的验收。真实维护者是否已创建或后台是否有数据不通过读取真实 `data/` 来推断。

历史 HTML 的内存保存、模拟管理权限、对象 URL、分享 fragment 也不是后台持久化或微信行为。原型入口只用于回看设计，不以其中「精选 / 作品」、创作状态和「技术未定」等历史措辞覆盖当前实现。
